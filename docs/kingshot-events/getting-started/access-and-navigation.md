# Choosing Scope and Understanding Access

Access answers two questions: what may this account do, and in which kingdom or alliance may it do it? Navigation and actions reflect both answers plus current module and subscription availability.

## Choose context before acting

Use the available kingdom or alliance selector. Some assignments lock a selector to one community. Recheck it before adding a player, applying an import, entering a result, reviewing Analytics, or publishing Castle Positions. A valid value saved in the wrong community is still wrong.

Changing scope can change navigation, player choices, events, analytics population, premium availability, and row actions. Unsaved form input should not be assumed to move with the selector.

## Navigation groups

**Workspace** contains active records and event views. **Discover** contains Updates, Knowledge Hub, and Lab. **My Tools** contains personal results such as rewards or appointments. **Input** contains manual entry, imports, and reports. Management or settings groups appear only for relevant assignments.

## When access is missing

An absent menu item, disabled action, locked premium panel, forbidden page, or empty scoped selector can have different causes. Confirm sign-in, player link, active community, role assignment, subscription feature, module availability, and whether the record is deleted or archived. A direct URL does not override access.
