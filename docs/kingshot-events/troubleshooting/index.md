# Problem Catalog

Match symptoms to access, scope, status, data, or browser causes and preserve useful evidence. This guide is the decision point for all users: it explains where to begin, what changes with scope or role, and which focused guide answers the next question.

## What this guide helps you decide

The main decision is whether to **collect enough evidence to resolve or report the problem**. Start by reading the scope label and the record status. A control can be present but unavailable when your membership, role, plan access, current status, or selected community does not permit the change. That distinction is intentional: visibility helps you understand the workflow, while availability protects shared records.

Use this page when you need to start with the visible symptom, then test scope, status, role, and data. It is not a promise that every account sees every action. Public pages, signed-in features, role-restricted controls, subscription-backed capabilities, and intentionally private administration are documented as different availability classes.

## Before you begin

- Confirm the signed-in identity and the player link shown in the account area.
- Read the current kingdom, alliance, or personal scope before changing data.
- Open the record itself instead of relying on a notification or an old browser tab.
- Check whether the status is Observed, Isolated, Resolved, or Escalated.
- If the action affects other people, agree on the intended outcome before saving or publishing.

## Controls and information you will use

The relevant controls are: **Start with the visible symptom, then test scope, status, role, and data**. Labels may be shortened on a narrow screen, but the scope name, status, primary action, and confirmation remain part of the same task. Filters change the current view; they do not silently move or rewrite the underlying record. A save changes a draft or editable record. Apply, approve, publish, restore, or award are separate decisions when the workflow requires review.

## Complete the task

1. **Record symptom.** Confirm the page title, signed-in identity, and selected scope before entering or changing anything.
2. **Check context.** Read existing values and status messages. If information is missing, stop and gather it rather than guessing.
3. **Try safe test.** Use the available control and review the preview, comparison, or warning. A disabled control usually points to a missing prerequisite.
4. **Report evidence.** Read the success message and reopen the affected record. For shared work, verify that the next responsible role can see the expected state.


## Status and role differences

| Status | What it means to the reader | Sensible next action |
| --- | --- | --- |
| **Observed** | The task is at its starting or neutral state. | Continue with record symptom. |
| **Isolated** | Work has progressed but another check or decision remains. | Continue with check context. |
| **Resolved** | Work has progressed but another check or decision remains. | Continue with try safe test. |
| **Escalated** | The workflow reached a final or constrained state. | Verify the outcome and history. |

For problem catalog, all users see the records and outcomes their current responsibility permits. Alliance roles act within their alliance, while granted kingdom roles can coordinate across communities without silently taking ownership of every source record. Plan access can reveal troubleshooting capabilities, but it never replaces the role, status, and scope checks described above. Platform-wide administration remains outside this public handbook.

## Saving, review, and history

While working in problem catalog, editable values should show a saved state before you leave. Review keeps check context separate from the later decision to try safe test. Applying or publishing makes the agreed outcome visible to its intended audience. If removal, rollback, or restore is supported here, authorized readers retain enough history to understand the change. Reopen the source record before repeating report evidence.

## If the result is not what you expected

- **The problem catalog action is missing:** confirm the selected scope, membership, role, and feature availability.
- **The action is disabled:** inspect required fields and the current status; a locked or final record may need a correction or review path.
- **The list looks unchanged:** clear view filters and reopen the source record before submitting again.
- **Another person sees a different result:** compare scope, date window, role, and publication state.
- **You need support:** record the page title, scope name, visible status, time, and safe steps to reproduce. Do not include passwords, payment details, or private screenshots.
